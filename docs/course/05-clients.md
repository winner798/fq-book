# 05｜Windows / Android 客户端实验：从“会点按钮”到看懂每一步

**本课目标**：在已有合法、可信的服务配置下，知道一个节点为什么工作、分流哪里起作用、怎样验证结果。

> 本课不提供免费节点、未知订阅或第三方配置仓库。不要将真实订阅链接、密码或令牌上传 GitHub，也不要随便导入他人写的复杂规则。

## 先画清配置结构

使用 Mihomo 内核的 Clash 系客户端，通常涉及：

```text
软件图形界面 → Mihomo 内核
                ├─ 入站：HTTP/SOCKS 端口、TUN
                ├─ DNS：域名如何解析
                ├─ 规则：决定出口 DIRECT / PROXY
                └─ 出站节点：远端地址、端口、协议、凭据
```

**订阅**只是一种分发配置的方式，不是“VPN 协议”；它可能包含节点、分组与规则。远端服务本身仍需要有效账号和可达的服务器。

## Windows：先从系统代理做实验

1. 安装来自项目官方渠道且与你系统匹配的 Mihomo/Clash 系客户端。核对项目名称与发布页；不要使用来源不明的修改版。
2. 导入**自己拥有或可信提供方授权**的配置；确认客户端已加载配置，核心进程正常运行。
3. 找到本地混合代理端口（例如 `7890`，具体以界面为准）。开启**系统代理**，先保持 TUN 关闭。
4. 在界面打开连接记录，访问 `https://example.com`，观察是 `DIRECT` 还是某个节点。修改一次规则，观察变化。
5. 关闭系统代理，再刷新页面，看看请求是否还进入客户端；这能区分“浏览器走代理”和“TUN 接管”。

PowerShell 进行独立验证（**将 7890 改为自己界面上的 HTTP/mixed 端口**）：

```powershell
curl.exe -I https://example.com
curl.exe -x http://127.0.0.1:7890 -I https://example.com
```

第一个命令不强制指定代理（但 curl 仍可能受环境变量等影响）；第二个明确走本地 HTTP 代理。若客户端只提供 SOCKS5 端口，使用 `--socks5-hostname 127.0.0.1:端口`，不要把端口类型混写。

## Android：本地 VPN 接管是什么？

Android 上很多代理客户端通过系统的 `VpnService` 接口建立虚拟网络接口。手机会弹出 VPN 授权提示，但**并不意味着远端协议就是 WireGuard/OpenVPN**。有些软件使用 VPN 接口把流量送入代理内核，再转向不同的代理节点。

依次测试：

1. 使用已知可信配置，确认节点可用；记录模式为规则/全局/直连中的哪一种。
2. 检查“按应用代理”“绕过局域网”“DNS”“IPv6”设置；先使用默认安全配置，不一次修改五项。
3. 切换 Wi-Fi 与移动数据，比较网络表现；记下是“连接节点失败”还是“仅某个 App 失败”。
4. 如果 VPN 接口被另一个应用占用，Android 可能不允许两个普通 VPN 服务同时保持接管；先检查系统 VPN 状态。

## 最容易踩的四个坑

- **全局 ≠ 所有程序必走远端**：先看流量是否被接管。
- **测速成功 ≠ 所有域名成功**：测速地址、协议、解析方式可能不同。
- **系统代理 ≠ TUN**：一个是应用选择使用的代理配置，一个是系统网络路由/捕获。
- **DNS 走直连而网页走代理**：可能造成域名解析差异；见第 09 课。
