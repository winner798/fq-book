# 第四课：从零搭建可验证的客户端—服务器链路

本实验先使用标准 HTTPS 服务学习全链路，再学习专用代理或 VPN。这样每一步都有清楚的故障边界，不会在还不理解 TCP、证书和防火墙时直接执行未知一键脚本。

## 实验目标

在有授权的 VPS 上部署一个只返回测试页面的 HTTPS 服务，并从 Windows/Android 客户端访问。准备：服务器、域名（或临时测试域名）、SSH 密钥、可用的 80/443 入站策略。域名的 A/AAAA 记录必须指向实际可访问的服务器地址。

## 分层步骤

1. **服务器层**：SSH 登录，更新系统，检查 `ip addr`、`ip route`。
2. **DNS 层**：配置域名解析，使用 `nslookup` 验证答案；注意缓存与生效时间。
3. **网络层**：按需开放 TCP 80/443，确认云安全组与主机防火墙规则。
4. **应用层**：安装并启动受维护的 Web 服务器（例如 Caddy），配置站点域名与测试页面；自动 HTTPS 需要域名解析、证书颁发条件及端口可达性满足要求。
5. **验证层**：本机用 `curl -I https://你的域名`，手机浏览器访问同一域名，对比 HTTP 状态与证书信息。
6. **排障层**：失败时依次检查 DNS、路由、端口监听、防火墙、TLS 证书和应用日志。

## 为什么不直接运行陌生脚本？

未知脚本可能更改防火墙、SSH 设置、系统服务和密钥。先理解每一层，再选择 WireGuard 或代理服务端方案，并在隔离测试环境中配置。
