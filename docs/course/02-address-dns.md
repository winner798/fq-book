# 02｜IP、端口、DNS、路由、网关与 NAT

**本课目标**：不再混淆“找得到主机”和“连得上服务”，学会阅读网络路径。

## 从地址和房间号入手

- **IP 地址**像楼的地址，定位网络接口；有 IPv4、IPv6。
- **端口号**像房间号，帮助操作系统把 TCP/UDP 数据交给相应的程序。`443`、`22`、`51820` 是常见例子，但“某个端口必定运行某协议”并不成立。
- **DNS**像地址簿，把域名映射到 DNS 记录（常见 A/AAAA）；DNS 不是承载网页内容的通道。
- **路由表**像交通指示牌，决定“下一跳从哪个网络接口出去”。
- **网关**是转发到别的网络的下一跳，不是“所有流量都必须经过的唯一服务器”。

```text
example.com --DNS--> 目标 IP
客户端IP:临时端口 --TCP/UDP--> 目标IP:服务端口
             ↑                   ↑
           出发点               目的地
```

浏览器访问 `https://example.com` 时，名字解析成功只是第一关；还要找到路由，并且目标端口有程序监听。

## NAT 到底做了什么？

家里手机 `192.168.1.10`、电脑 `192.168.1.20` 常共用路由器的一个公网 IPv4 出口。家庭路由器的 NAT（常见是 NAPT）会记录类似映射：

```text
手机 192.168.1.10:51234 → 路由器公网IP:40001 → 网站:443
返回数据匹配路由器映射表 → 找回手机:51234
```

NAT 的主要用途是地址/端口转换，不等于网络加密，也不天然保证安全。**没有公网 IPv4 的家庭网络可能还经过运营商 CGNAT**，导致外部设备难以主动连接家中的服务。

IPv6 不一定需要这类 IPv4 NAT，但依然有防火墙与路由问题。不要为了“提升 NAT 类型”就贸然打开 DMZ、UPnP 或关闭防火墙。

## 重要区别：域名与 IP

一个网站可有多个 IP；多个网站也可能共用一个 IP（如 CDN）。HTTPS 还会使用主机名相关的 TLS/HTTP 信息，所以“把域名随便替换为 IP”经常会失败。修改 Hosts 只影响部分系统解析路径，不能保证绕过 IP 封锁、TLS 验证或浏览器自己的 DNS 配置。

## 简单实验

Windows PowerShell：

```powershell
ipconfig /all
route print
nslookup example.com
tracert example.com
```

Linux：

```bash
ip addr
ip route
getent ahosts example.com
tracepath example.com
```

**观察**：本机 IP、默认网关、DNS 服务器分别是什么？`tracert` 中间出现 `*` 不一定是中断，路由器可能不响应探测报文。

## 自测

1. 把 DNS 改为公共服务器能否修复所有 HTTPS 证书错误？
2. 如果手机和电脑都用了 `192.168.x.x`，为什么仍能同时访问互联网？
3. 家庭宽带有公网 IPv4，为什么还需要端口映射？

**答案**：1）不能，证书错误有多个成因，不应跳过证书告警；2）通常通过 NAT 的不同连接映射；3）路由器仍需知道入站连接发给哪台内部设备，还要满足防火墙限制。
