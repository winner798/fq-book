# 第一课：打开一个网站时发生了什么？

## 1. 从生活直觉开始

把网站看作商店：域名是店名，DNS 是查询地址的电话簿，IP 是网络地址，端口是服务入口。这个比喻只用于入门：真实网络还涉及路由、连接和加密。

## 2. 一次访问的六步

1. 浏览器解析 URL，判断协议、域名、端口和路径。
2. 查询 DNS，将域名解析为 IP（也可能命中缓存）。
3. 系统按路由表选择下一跳，经局域网网关和运营商网络转发。
4. HTTPS 通常建立 TCP 连接并完成 TLS 握手；HTTP/3 则基于 QUIC/UDP。
5. 浏览器发送 HTTP 请求，服务器返回状态码、响应头和内容。
6. 浏览器解析 HTML，继续请求 CSS、JS、图片并渲染。

```text
浏览器 → DNS 查询
浏览器 → 本机路由 → 家庭路由器/NAT → ISP → 目标服务器
浏览器 ⇄ 服务器：传输连接 + 加密握手 + HTTP 请求/响应
```

## 3. 关键概念

- **IP**：网络层寻址，不等于人的身份。
- **端口**：传输层区分服务，443 常用于 HTTPS，但不是强制规定。
- **DNS**：负责名称解析，不负责签发网站 TLS 证书。
- **TCP**：提供有序可靠字节流；UDP 提供数据报，不保证可靠性。
- **TLS**：在通信双方之间提供身份验证与加密保护；证书错误不应直接忽略。
- **NAT**：常把内网地址和端口映射为公网连接信息，并非所有网络都使用 NAT。

## 4. 动手实验

Windows PowerShell：

```powershell
nslookup example.com
Test-NetConnection example.com -Port 443
tracert example.com
curl.exe -I https://example.com
```

依次观察：DNS 答案、TCP 端口连通性、可能的路由跳点、HTTP 响应头。部分路由器屏蔽探测包，因此 `tracert` 超时不一定代表网页不可访问。

## 5. 常见误区

- 能 ping 通不代表 HTTPS 一定正常；ping 不通也不一定代表网站故障。
- 更换 DNS 不会自动修复所有 TLS 证书错误，证书异常还需检查时间、代理拦截和信任链。
- 使用代理时，域名解析可能由本地或远端执行，取决于客户端模式和配置。
