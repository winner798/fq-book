# 01｜客户端、服务器与一次完整网页访问

**本课目标**：理解客户端与服务器的角色，能画出浏览器到网站的路径，区分“本地软件”和“云端机器”。

## 从生活类比开始

餐厅里，点菜的人发出请求，厨房处理并返回结果。但“客户端/服务器”不是人的永久身份，而是**一次通信中请求服务和提供服务的角色**。浏览器通常是客户端；网站后端通常是服务器。你的电脑也能运行一个服务端程序，让其他设备访问。

“服务器”常有两种含义：一台运行程序的计算机（物理机、虚拟机、云主机），或一个正在监听网络请求的程序（Web 服务、SSH 服务、代理服务）。**买了一台 VPS，并不意味着它自动变成代理服务器**；必须有相应的软件、身份认证、端口与网络规则。

## 用打开网页说明全链路

假设你在浏览器输入 `https://example.com`：

1. 浏览器分析 URL：`https` 是协议，`example.com` 是主机名，未显式写端口，HTTPS 常用 TCP 443。
2. 浏览器和系统尝试通过 DNS 获取网站的可用 IP 地址（也可能已有缓存）。
3. 操作系统查路由表，把数据发给合适的接口；家中通常先经过路由器。
4. 数据包经运营商与中间路由器，到达目标服务器或其 CDN 接入点。
5. 传输层建立 TCP 连接（或 HTTPS/3 使用 QUIC/UDP），进行 TLS 握手。
6. 浏览器发送 HTTP 请求，服务端返回状态码、响应头和页面资源。
7. 浏览器还可能请求 CSS、JavaScript、图片以及其他域名上的资源。

注意：DNS、传输层和 TLS 不一定每次都从头发生；连接复用、缓存、HTTP/3 会改变细节。

## 三个容易混淆的地址

| 名称 | 示例 | 它指向哪里 |
| --- | --- | --- |
| 本地回环地址 | `127.0.0.1` | 当前这台设备自己 |
| 局域网地址 | `192.168.1.8` | 家里/学校内网的一台设备 |
| 公网 IP | 由运营商或云平台分配 | 互联网上可路由的地址（不保证可从外部主动连接） |

例如，Clash/mihomo 的 `127.0.0.1:7890` 是**电脑本机的代理入口**，浏览器连接的是自己；远端节点可能是另一台 `服务器IP:端口`。这两者不能混为一谈。

## 客户端、服务端都有什么

客户端负责生成请求、根据规则决定是否走代理、向服务器认证并展示结果。服务器负责监听、认证、建立到目标站的新连接、转发流量、返回结果。DNS 解析发生在哪一端要取决于代理类型和配置。

```text
[浏览器] --HTTP代理--> [本地客户端:7890]
                              |
                        [加密传输连接]
                              |
                       [远程服务端:端口]
                              |
                       [目标站点:443]
```

## 不用任何代理也能做的实验

Windows PowerShell：

```powershell
nslookup example.com
Test-NetConnection example.com -Port 443
curl.exe -I https://example.com
```

- `nslookup`：问 DNS；它成功，不代表网站 TCP/TLS 一定成功。
- `Test-NetConnection`：测试 TCP 443 是否能连接；成功，不代表 TLS 证书有效或 HTTP 一定正常。
- `curl.exe -I`：发送 HTTP HEAD 请求；返回状态码可以是 200、301 等，不必强求一定是 200。

## 自测

1. 为什么把浏览器里的代理设置为 `127.0.0.1:7890` 并不会直接连接境外服务器？
2. “服务器有公网 IP”是否等于“任何人都能访问它的任意端口”？
3. DNS 已返回 IP，网页却打不开，应继续检查哪几层？

**答案**：1）先连接本机监听程序，再由它建立外部连接；2）否，还要检查服务监听、防火墙、安全组、路由；3）连接、TLS、HTTP 以及本地代理/分流规则。
