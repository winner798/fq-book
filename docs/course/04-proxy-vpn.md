# 04｜代理、VPN、隧道与 TUN：看懂数据到底走哪里

**本课目标**：区分本地代理端口、远端服务端口、系统代理、TUN 和真正的 VPN。

## 不用任何中转

```text
浏览器 → 操作系统 → 互联网 → 网站
```

## 使用正向代理

```text
浏览器 → 本地HTTP/SOCKS入口 → 代理客户端 ==== 远端服务端 → 网站
             127.0.0.1:7890         加密链路
```

本地入口通常只服务本机应用；远端服务端需要实际运行相应软件。不同协议会决定客户端与服务端如何认证、加密和转发。HTTP 代理通常通过 CONNECT 方法转发 HTTPS 连接；SOCKS5 提供目标地址、端口等请求格式，也可在具体实现中支持 UDP 转发。

**SOCKS5 不是直接把任意 IP 包全部搬走**；它是代理协议，不等同于三层 IP 隧道。不要死记“SOCKS 属于 OSI 某一层”。

## VPN / 隧道

```text
应用 → 操作系统 IP 路由 → 虚拟网络接口(TUN)
                           ║
                      加密的隧道
                           ║
                      VPN 远端服务器
                           → 目的网络/互联网
```

TUN 是处理 IP 包的虚拟网络接口；但**有 TUN 不代表一定使用 WireGuard，也不代表一定全部流量进隧道**。实际要看路由、策略、DNS 和应用绕过规则。许多代理客户端能通过 TUN 捕获系统 IP 流量，再根据规则转为代理协议连接——这在表现上很像 VPN，底层协议并不相同。

## 对比表

| 技术 | 典型捕获范围 | 常见用途 | 误区 |
| --- | --- | --- | --- |
| 浏览器 HTTP 代理 | 配置了代理的 HTTP(S) 请求 | 浏览器访问 | 不是全设备代理 |
| SOCKS5 | 主动使用该入口的应用流量 | 多应用 TCP，部分 UDP | 不是任意 IP 包 |
| 系统代理 | 遵循系统设置的应用 | 桌面常规访问 | 不是所有进程都遵守 |
| TUN 捕获 + 代理内核 | 路由到虚拟接口的 IP 流量 | 分流、透明接管 | DNS 与 IPv6 仍需检查 |
| WireGuard VPN | 路由指向 WireGuard 的网段 | 站点互联、远程访问、全隧道 | `AllowedIPs` 与服务器转发必须匹配 |

## 为什么“规则模式”不同于“全局模式”

Mihomo/Clash 的模式通常决定**已经进入代理内核的连接**选择哪个出口：
- `Rule`：根据域名/IP/规则集决定直连还是代理。
- `Global`：一般将进入内核的请求交给所选代理组。
- `Direct`：一般直接连接，不经远端节点。

但如果一个程序根本不遵守系统代理，且 TUN 又没接管它，模式切为 Global 也未必影响它。

## 一张排查逻辑图

```text
应用发请求
  ├─ 有无进入本地代理内核？没有 → 检查系统代理/TUN/应用设置
  └─ 进入了 → 匹配了哪条规则？
                 ├─ DIRECT → 本地网络直达目标
                 └─ PROXY  → 远端服务器是否可连、认证是否正确？
```

## 自测

1. 电脑开了“系统代理”后，某游戏仍直连，是否一定是节点坏了？
2. `127.0.0.1:7890` 和 `203.0.113.10:443` （文档示例地址）分别是什么角色？
3. 为什么用 TUN 时还需要理解 DNS 和路由？

**答案**：1）未必，应用可能不走系统代理；2）本地入口与远端服务地址；3）捕获、域名解析和真实出口是独立环节，可能绕过或泄漏。
