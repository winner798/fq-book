# 第二课：代理、VPN、系统代理和 TUN 到底是什么？

## 1. 为什么要有代理？

普通直连路径：`应用 → 网络 → 目标网站`。使用正向代理后：`应用 → 代理入口 → 目标网站`。代理替应用建立或转发连接；是否加密、在哪里解析 DNS、目标网站看到什么地址，取决于协议与配置。

## 2. 四个容易混淆的概念

| 概念 | 核心作用 | 典型边界 |
| --- | --- | --- |
| HTTP 代理 | 转发 HTTP 请求或使用 CONNECT 建立隧道 | 应用需要支持代理 |
| SOCKS5 | 转发多种类型的连接 | SOCKS5 本身不等于加密 |
| 系统代理 | 向遵循系统设置的应用公布代理入口 | 不保证所有程序都遵循 |
| TUN/VPN | 在虚拟网络接口或系统 VPN 框架接管 IP 流量 | 仍取决于路由、排除项与系统限制 |

**注意**：Clash/Mihomo 是规则与连接管理核心，不等于某一种单独的 VPN 协议；界面显示“全局”也不意味着操作系统所有流量必定经过代理。

## 3. 一条远端代理链路

```text
浏览器/APP
   ↓（系统代理或 TUN 捕获）
本机代理客户端（规则匹配、DNS 策略）
   ↓（本机到远端的连接；按协议决定加密）
远端代理服务器（公网 IP、监听端口、认证）
   ↓
目标网站（看到的来源地址通常为远端出口）
```

客户端与服务器不是同一个程序角色。**客户端负责接入和路由决策，服务器负责接受连接并向目标转发**；不同架构可能增加中转、反向代理或网关。

## 4. 分流规则如何生效？

规则引擎可能根据域名、IP、进程等条件选择 DIRECT、PROXY 或 REJECT。域名规则和 IP 规则受 DNS 解析时机影响；若 DNS 绕开预期路径，可能产生隐私和可用性问题。

## 5. 动手验证

1. 在已有客户端中记录 HTTP/SOCKS 监听地址与端口，例如 `127.0.0.1:7890`（仅示例，实际以软件显示为准）。
2. Windows PowerShell 执行 `curl.exe -I https://example.com`，记录直连结果。
3. 执行 `curl.exe -x http://127.0.0.1:7890 -I https://example.com`，对比结果；端口需替换为真实监听值。
4. 切换规则模式并观察客户端日志中的规则命中和出口选择。不要仅凭网页能打开就判断所有应用都经过代理。
